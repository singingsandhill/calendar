# 주식 갭&눌림목 봇 — 한국투자증권 KOSPI/KOSDAQ

> **대상 독자:** 봇을 운영하거나 코드를 유지보수하는 사람  
> **목적:** "봇이 왜 이렇게 작동하는가"를 이해하기 위한 레퍼런스

---

## 1. 전략 개요

### 갭&눌림목(Gap & Pullback)이란?

주식이 전날 종가보다 **높게 시작(갭 업)** 한 뒤 잠시 조정을 받다가 **다시 반등**하는 순간을 노리는 전략이다.

```
가격
  ↑
  │              ┌─── TP3 목표
  │         ┌───┤
  │    ← 고점 형성 후
  │   ┌─┘   하락(눌림목)
  │  ┌┘
갭 업│         └┐  ← 반등 확인 → 진입!
  ─ ┘           └──────────────────────────
  │
전일 종가 ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─
```

**직관적 설명:**
1. 좋은 소식으로 주가가 갭 업 시작 → 초반 강세 종목 선별
2. 초기 모멘텀에 매수한 사람들이 차익 실현 → 일시적 하락(눌림목)
3. 하락이 과도하지 않으면 지지선에서 반등 → **이 순간이 진입 타이밍**
4. 갭 방향(상승)으로 다시 움직임 → 단기 차익 실현

### 왜 09:20~11:20인가?

```
09:00~09:20: 장 초반 혼조 구간
  - 호가 스프레드가 넓음
  - 체결강도 집계가 불안정 (KIS API 초기값 0 반환)
  - 갭이 실제 관심인지 알 수 없음

09:20~11:20: 봇의 거래 시간
  - 체결강도 집계 안정화 완료
  - 갭이 장 시작 20분 후에도 유지되면 관심 종목으로 확인됨
  - 오전 장 유동성이 가장 높은 시간대

11:20 이후: 강제 청산
  - 오후로 갈수록 유동성 감소, 변동성 증가
  - 당일 수익을 확정하고 익일 리스크 없음
```

### 잘 작동하는 조건

- 갭 상승이 3~5% 사이 (갭 점수 벨 커브의 최고 구간 — Floor 는 0.5~15% 지만 4%에서 멀어질수록 점수가 낮아진다)
- 체결강도 95 이상 (스크리닝 Floor) — 진입 검증 단계에서는 100 이상을 본다
- 시가총액 500억 이상 (유동성 확보)
- 눌림목이 -1.5% ~ -5% 범위 (너무 얕으면 비용 게이트를 못 넘고, 너무 깊으면 하락 추세)

### 불리한 조건

- 공휴일 (필터는 있으나 `stock.trading.holidays` 가 비어 있어 실제로는 주말만 차단된다)
- 시장 급락 구간 (손절이 통상 진입가 대비 약 -1.2% 라 노이즈에도 자주 발동)
- KIS API 점검 시간

## 3. 종목 스크리닝

### 유니버스 (그날 스크리닝 대상)

거래일 1회 스냅샷으로 만든다 — `pinned` ∪ KIS 거래량순위 상위 30 ∪ 정적 폴백 70종목의 합집합:

- `stock.universe.pinned` — 항상 포함할 종목. 현재 운영값은 빈 배열이다.
- 거래량순위(`rank-api-top: 30`) — 08:30 에는 당일 거래량이 없어 호출하지 않고, 09:20
  스크리닝 시점에 조회한다.
- `stock.universe.fallback-codes` 70종목 (코스피 대형주 / 2차전지·전기차 / 반도체·IT·게임 /
  바이오·제약 / 코스닥 중소형 / 코스닥 성장주 / 금융·자동차) — 거래량순위가 요청한 30건에
  **미달하면** 합집합으로 보강한다. 1건 응답이 정적 안전망을 통째로 껐던 2026-08-03 사고
  이후의 규칙이다 (ADR stock/algorithm/0010).

### 1단계: Floor 필터 (Hard Cut)

다음 조건 중 하나라도 미충족이면 후보에서 제외:

```
① 거래 가능 상태: VI·거래정지·관리·정리매매·투자경고 종목은 제외

② 시가 데이터 존재 여부: 시가가 0이거나 없으면 제외 (장 초반 데이터 지연)

③ 갭 범위: 0.5% ~ 15%
   - 0.5% 미만: 갭 아님, 모멘텀 없음
   - 15% 초과: 상한가 근처, 진입 불가

④ 체결강도: 95 이상
   - 소스는 주식현재가 체결(inquire-ccnl)의 tday_rltv — 시세 TR 에는 체결강도 필드가 없다
   - 95 미만: 매수보다 매도가 많음 → 제외
   - 0 또는 조회 실패(집계 미완료)는 데이터 부족으로 제외 (skip-zero-strength, 기본 true)

⑤ 시가총액: 500억 이상
   - 미만이면 소형주, 슬리피지/유동성 리스크 높음
```

### 2단계: 복합 점수 계산 (5가지 요소)

Floor 필터를 통과한 종목에 대해 0~100점 점수를 계산한다:

```
┌────────────┬──────┬────────────────────────────────────────────────────┐
│ 요소       │ 가중치│ 점수화 방식                                       │
├────────────┼──────┼────────────────────────────────────────────────────┤
│ 갭         │  30% │ 벨 커브: 4% 중심, σ=3%                           │
│            │      │ → 3~5% 갭이 최고점, 0%나 15%는 0점              │
│ 체결강도   │  25% │ 선형: 95~130 범위 정규화                          │
│            │      │ → 130 이상 = 100점, 95 = 0점                    │
│ 거래대금   │  20% │ 로그 스케일: 5억~500억 범위                       │
│            │      │ → 유동성 지표, 로그 스케일로 극단값 완화          │
│ 스프레드   │  15% │ 역수: 0~0.5% 범위 (작을수록 좋음)                │
│            │      │ → 매도호가-매수호가 차이가 작으면 고점수          │
│ 시가총액   │  10% │ 로그 스케일: 500억~10조 범위                      │
│            │      │ → 안정성 지표, 소형주 패널티                      │
└────────────┴──────┴────────────────────────────────────────────────────┘
```

### 갭 점수 벨 커브 — 왜 4%가 중심인가?

```
갭 점수
 100% │              ★ 최고점 (4% 갭)
      │           ╱     ╲
  75% │        ╱           ╲
      │     ╱                 ╲
  50% │  ╱                       ╲
      │╱                             ╲
   0% ├──────────────────────────────────── 갭%
      0%  2%  4%  6%  8%  10%  12%  15%

공식: 점수 = e^(-(갭-4)² / (2×3²))

이유:
- 2% 미만: 갭이 미미해서 초기 모멘텀 부족
- 3~5%: 충분한 갭이면서 과열되지 않은 "황금 구간"
- 7% 초과: 이미 급등, 눌림목이 너무 깊어질 가능성
- 15%: 상한가 근처, 추가 상승 여지 제한
```

### 3단계: 종목 선정

```
정렬: 복합 점수 내림차순
선정: 아래 두 관문을 모두 통과한 종목만, 상위 N개 (max-watchlist-size, 기본 10개)
      ① 총점 ≥ min-score-threshold (40)
      ② 신호 점수(갭 점수 + 체결강도 점수) ≥ signal-min-score (25)
         — 유동성 팩터(거래대금·스프레드·시총 최대 45점)만으로 총점 임계를 넘기던 왜곡 차단
조건에 맞는 종목이 없으면 그날은 0건이 정상 (min-candidates 강제 선정은 제거됨, 키만 보존)
```

## 4. 8단계 상태 머신 ★ 핵심

각 종목은 아래 상태를 순서대로 거쳐야만 진입 가능하다.

```
┌──────────────────────────────────────────────────────────────────────┐
│                                                                      │
│  [WATCHING]                                                          │
│       │                                                              │
│       │ 현재가 ≥ 시가 × 1.015  (+1.5% 이상 상승)                  │
│       ▼                                                              │
│  [HIGH_FORMED]  ← 초기 강세 확인                                    │
│       │                                                              │
│       │ 현재가 ≤ 고점 × 0.985  (고점 대비 -1.5% 이상 하락)         │
│       │                                                              │
│       │                    고점 대비 -5% 초과 하락이면              │
│       │                              ↓                              │
│       │                    [FILTERED_OUT] ← 이탈, 더 이상 추적 안 함│
│       ▼                                                              │
│  [PULLBACK]  ← 눌림목 확인                                          │
│       │                                                              │
│       │ 현재가 ≥ 눌림목 저점 × 1.002  (저점 대비 +0.2% 반등)       │
│       │ + 진입 검증 (체결강도, 호가 불균형, 눌림목 시간)            │
│       ▼                                                              │
│  [ENTRY_READY]  ← 반등 확인, 매수 대기                              │
│       │                                                              │
│       │ 매수 주문 체결                                               │
│       ▼                                                              │
│  [ENTERED]  ← 포지션 보유 중                                        │
│       │                                                              │
│       │ 손절 / TP1 / TP2 / TP3 / 추적손절 / 시간청산               │
│       ▼                                                              │
│  [EXITED]  ← 청산 완료                                              │
│                                                                      │
└──────────────────────────────────────────────────────────────────────┘
```

### 각 상태 전환 조건 상세

| 전환 | 조건 | 이유 |
|------|------|------|
| WATCHING → HIGH_FORMED | 현재가 ≥ 시가 × 1.015 | 갭 업 이후 최소 +1.5% 추가 상승이 있어야 실제 모멘텀으로 인정 |
| HIGH_FORMED → PULLBACK | 현재가 ≤ 고점 × 0.985 | 고점에서 -1.5% 이상 하락 시 눌림목 구간으로 진입 |
| HIGH_FORMED·PULLBACK → FILTERED_OUT | 현재가 < 고점 × 0.950 | -5% 초과 하락 → 단순 눌림목이 아니라 하락 추세로 판단 |
| PULLBACK → ENTRY_READY | 저점 × 1.002 이상 반등 + 진입 검증 통과 | 반등 확인 + 매수 압력 확인 |
| ENTRY_READY → ENTERED | 매수 주문 체결 | 실제 포지션 진입 |
| ENTERED → EXITED | 청산 조건 (섹션 6) | 수익 실현 또는 손실 제한 |

## 5. 진입 조건 상세

ENTRY_READY 전환 시 3가지 조건을 검증한다.

### 소프트 검증 (softEntryValidation = true, 기본값)

**3개 중 2개 이상 충족**하면 진입 허용 (2/3 규칙)

```
조건 1: 체결강도 ≥ 100
  - 소스: 주식현재가 체결(inquire-ccnl)의 tday_rltv
  - 의미: 매수 압력이 매도 압력과 같거나 큼
  - 조회 실패·미집계(null 또는 0)는 FAIL — 데이터 부족은 통과가 아니다

조건 2: 호가 불균형(Order Imbalance) ≥ 1.0
  - 공식: 총 매수호가잔량 / 총 매도호가잔량
  - 의미: 매수 대기 주문이 매도 대기 주문보다 많음
  - 호가 조회 실패는 FAIL

조건 3: 눌림목 지속 시간 3~15분
  - 3분 미만: 너무 빠른 반등 → 가짜 반등(휩소) 가능성
  - 15분 초과: 오래된 눌림목 → 패턴이 식었음
  - 풀백 시작 시각이 없으면 FAIL (soft 2/3 의 실질 문턱이 내려가는 것을 막는다)
```

### 하드 검증 (softEntryValidation = false)

3개 조건 모두 충족해야 진입 허용 (더 보수적)

## 6. 청산 전략 — 3단계 익절

### 청산 우선순위 (판정 순서)

| 구분 | 조건 | 청산 수량 | 순서 |
|---|---|---|---|
| 손절 | 현재가 ≤ max(풀백저가 × 0.99, 진입가 × 0.98) — 통상 진입가 대비 약 -1.2% | 잔여 100% | 1 |
| 추적손절 | 현재가 ≤ 추적고점 × 0.98 (-2.0%), 단 손익분기(진입가 × 1.0043) 아래로는 내리지 않음 | 잔여 100% | 2 |
| TP3 | 현재가 ≥ 진입가 × 1.10 (+10%) | 잔여 100% | 3 |
| TP2 | 현재가 ≥ 당일 고점 | 잔여의 60% | 4 |
| TP1 | 현재가 ≥ 진입가 × 1.05 (+5%) | 진입수량의 50% (잔여수량 캡) | 5 |
| 시간청산 | 11:20 (종목당 최대 3회 재시도, 실패 시 메일 알림) | 잔여 100% | 최후 수단 |

- **TP1·TP2·TP3 는 독립 트리거다.** 선행 단계가 발동하지 않았어도 상위 트리거 조건이 맞으면
  즉시 발동한다.
- **TP1·TP3 앵커는 진입가 고정, 손절 앵커는 풀백저가(진입 근거)다.** 매 틱 갱신되는 당일고가를
  앵커로 쓰는 것은 TP2 뿐이다. TP3 가 당일고가 앵커였던 시절에는 5초 폴링 간격에 +10% 점프가
  필요해 수학적으로 도달 불가였다.
- **추적손절은 TP1·TP2·TP3 중 하나라도 실행되면 활성화**되고, 활성화 시점에 스탑가가 즉시 설정된다.
- **TP 는 가격 조건만으로 발동하지 않는다.** 아래 순이익 게이트를 함께 통과해야 한다.

### 시나리오 예시

```
진입가: 10,000원 / 100주 매수 (진입금액: 1,000,000원)
풀백저가: 9,900원 → 손절가 = max(9,900 × 0.99, 10,000 × 0.98) = 9,801원 (-1.99%)

─────────────────────────────────────────────────────────────────────────
시나리오 1: 상승 지속 (TP2 → TP1)

  10,200원 (당일 고점) 도달 → TP2 실행
    → 100주 × 60% = 60주 매도, 잔여 40주
    → 추적손절 활성화 (추적고점 10,200원, 스탑 = 10,200 × 0.98 = 9,996원 →
       손익분기 10,043원보다 낮으므로 10,043원으로 올려 잡음)

  10,500원 (진입가 +5%) 도달 → TP1 실행
    → 진입수량 50% = 50주지만 잔여 40주로 캡 → 40주 매도, 잔여 0주

  (잔여가 남아 있었다면 11,000원(진입가 +10%)에서 TP3 로 전량 청산)

─────────────────────────────────────────────────────────────────────────
시나리오 2: 부분익절 이후 하락 (추적손절)

  10,200원 → TP2 실행 (60주 매도, 잔여 40주)
  10,400원 → 추적고점 갱신, 스탑 = 10,400 × 0.98 = 10,192원
  가격 하락 → 10,192원 도달 → 추적손절 발동
    → 잔여 40주 전량 청산 (손익분기 하한이 있어 최악의 경우도 본전)

─────────────────────────────────────────────────────────────────────────
시나리오 3: 즉시 하락 (손절)

  진입 후 하락 → 9,801원 도달 → 잔여 100% 즉시 청산

  결과: 약 -2.0% 손실 확정 (풀백저가가 진입가에 가까울수록 손실은 작아진다)
─────────────────────────────────────────────────────────────────────────
```

### TP 실행 시 수수료 포함 수익률 확인

TP1~TP3는 수익이 충분할 때만 실행한다 (수수료·세금·슬리피지를 내고도 이익이 나야 함):

```
비용 구조:
  매수 시: 거래금액 × 0.015% (증권사 수수료)
  매도 시: 거래금액 × 0.015% + 거래금액 × 0.20% (수수료 + 매도 세금)
  왕복 수수료·세금: 0.23%
  시장가 슬리피지 가정 0.2% 를 더한 실효 청산 비용: 0.43%

순이익 게이트 (TP1·TP2·TP3 공통):
  수수료 차감 손익률 − 슬리피지 ≥ 시간 감소 최소 수익률
  미달이면 가격 조건을 충족해도 발동을 건너뛴다 — TP2(당일고가 도달)도 예외가 아니다

시간 감소 최소 수익률:
  09:20(trading-loop-start) 이전: 0.5%
  09:20~11:20: 0.5% → 0.1% 로 선형 감소
  11:20(final-exit-time) 이후: 0% (강제청산 구간이라 게이트를 열어 둔다)
```

## 7. 시간 감소 수익률 임계값

오전에는 수익 기준을 높게 유지해서 성급한 청산을 막고,
장 마감 가까울수록 낮춰서 확실한 청산을 유도한다.

```
최소 수익률
  0.5% ━━━┓
          ┃
  0.4%     ┃
            ┃
  0.3%       ┃
              ┃
  0.2%         ┃
                ┃
  0.1%           ┗━━━━━━━━ 11:20 이후 0%
       ────────────────────────────────────
        09:20    10:00    10:40    11:20

공식: threshold = 0.5% − (0.5% − 0.1%) × 경과비율
     경과비율 = (현재시각 − trading-loop-start) / (final-exit-time − trading-loop-start)
     - 09:20 이전: 0.5%
     - 09:20~11:20: 위 식으로 선형 감소 (11:20 직전 ≈ 0.1%)
     - 11:20 이후: 0%
```

두 종점은 상수가 아니라 설정(`stock.trading.trading-loop-start`, `stock.exit.final-exit-time`)에서
유도한다. 09:10 / 15:15 가 코드에 박혀 있던 시절에는 봇 운영 창(09:20~11:20)이 365분 곡선의
약 36% 만 지나가, 설정에 적힌 후반 완화 구간에 **도달할 수 없었다**.

## 8. 수수료 & 세금 구조

### 한국투자증권 수수료 체계

```
매수 수수료: 체결금액 × 0.015%   (risk.commission-rate 0.00015)
매도 수수료: 체결금액 × 0.015%
매도 세금:   체결금액 × 0.20%    (risk.sell-tax-rate 0.0020)
  - 코스피:        증권거래세 0.05% + 농어촌특별세 0.15%
  - 코스닥·K-OTC:  0.20% (농특세 없음)
  → 2026-01-01 이후 양도분 기준으로 두 시장 모두 매도측 0.20%
─────────────────────────────────────
왕복 수수료·세금: 0.015% × 2 + 0.20% = 0.23%
시장가 슬리피지 가정 0.2% 포함 → 실효 청산 비용 0.43%
  (risk.slippage-buffer 0.002 — 익절 게이트와 트레일링 손익분기 하한이 이 값을 쓴다)

예시: 10,000원짜리 100주 매수 후 10,500원(TP1)에 전량 매도
  매수 수수료: 1,000,000 × 0.015% = 150원
  매도 수수료: 1,050,000 × 0.015% = 158원
  매도 세금:   1,050,000 × 0.20%  = 2,100원
  ────────────────────────────────────────
  총 비용:    2,408원
  실수익:     50,000 - 2,408 = 47,592원 (약 +4.76%)
```

> 으로 먹히지만 원본과 문자 대조가 안 돼, 옛 파라미터로 조용히 되돌아가는 사고가 난다.

## 11. FAQ & 트러블슈팅

### "09:20에 스크리닝 결과가 0개예요"

```
체크 사항:
□ stock.bot.enabled = true 인가?
□ KIS API 키가 올바르게 설정되었는가?
□ 오늘이 거래일인가? (주말 제외 — 공휴일은 stock.trading.holidays 에 넣어야 걸러진다)
□ 유니버스가 정상 크기인가?
  grep "Universe refreshed" logs/stock-trading.log
  (거래량순위가 rank-api-top 미달이면 정적폴백 70종목이 합집합으로 들어와야 한다)
□ 어느 Floor 에서 떨어졌는가? 0건인 날은 로그 한 줄에 탈락 버킷이 전부 찍힌다:
  grep "0 selected from" logs/stock-trading.log
□ Floor 는 통과했는데 선정이 0건이면 관문 미달이다 — 총점 40 또는 신호점수 25 확인
□ API 토큰 발급에 실패했는지 로그 확인:
  grep "KIS access token" logs/stock-trading.log
```

### "체결강도가 항상 0으로 나와요"

체결강도는 시세 TR 이 아니라 주식현재가 체결(inquire-ccnl)의 `tday_rltv` 에서 읽는다 —
시세 TR 응답에는 체결강도 필드 자체가 없다.
장 초반에는 아직 집계 전이라 값이 없을 수 있고, 봇은 값 없음·0 을 **데이터 부족으로 보고
그 종목을 탈락시킨다**(`stock.screening.skip-zero-strength` 기본값 true).
09:20 이후에는 정상 집계된다.

### "손절이 너무 자주 발동해요"

```
손절가 = max(풀백저가 × (1 - risk.pullback-stop-buffer-percent 1.0%),
             진입가   × (1 - risk.max-stop-loss-percent    2.0%))
→ 통상 진입가 대비 약 -1.2%. risk.stop-loss-percent 는 레거시 키라 손절 계산에 쓰이지 않는다.

완화 방법:
  1. max-stop-loss-percent 를 2.5~3.0% 로 늘려 손실 캡을 넓힌다
  2. pullback-stop-buffer-percent 를 늘려 손절 앵커를 풀백저가에서 더 떨어뜨린다
  3. entry.pullback-max-percent 를 줄여 얕은 눌림목만 진입한다
  4. entry.soft-entry-validation 을 false 로 바꿔 진입 조건을 3/3 으로 강화한다

주의: 손절을 넓히면 평균 손실도 커진다. 손절 폭은 익절 폭·비용 게이트와 함께 봐야 한다.
```

### "공휴일에도 봇이 실행되려고 해요"

공휴일 필터는 있다 — 스케줄러가 주말과 `stock.trading.holidays` 목록을 함께 배제한다.
다만 현재 운영값이 `holidays: []` 라서 실제로 걸러지는 건 주말뿐이고,
공휴일이 평일이면 스케줄이 그대로 실행된다.
막으려면 `stock.trading.holidays` 에 yyyy-MM-dd 를 채우거나,
그날만 `stock.bot.enabled = false` 로 두어야 한다.

### "이메일이 오지 않아요"

```
체크 사항:
□ stock.mail.enabled = true 인가?
□ stock.mail.to 이메일 주소가 올바른가?
□ Gmail SMTP 설정이 되어 있는가?
  (spring.mail.host, spring.mail.username, spring.mail.password)
□ 로그에서 메일 오류 확인:
  grep "mail" logs/stock-trading.log
```
