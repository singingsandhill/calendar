## 3. 발견 (심각도 순)

> [V] 코드·실측으로 확인 / [I] 추론. 선행 감사 대비 상태를 각 항목 끝에 적는다.

### F1 [critical] 리밸런싱 = 1시간 이동평균 모멘텀에 자본 30~70% 를 8시간마다 재투입하는 손절 루프 [V]
- 국면: `RebalanceService.java:226-244` `determineTargetRatio` — `indicatorService.calculate(market)` 의 `ma60` 은 최근 60 **저장** 봉 평균.
  거래 없는 분이 생략되므로 벽시계로 ≈ 4시간(§2-2). 반환값은 0.70/0.30/0.50 뿐 — **0% 국면이 없다.**
- 전액 현금이면 `currentRatio=0`, 편차 0.30 또는 0.70 ≥ 0.10 → `executeRebalance:252-282` → `buyAndOpenPosition:106-137` 이 시장가 매수 후
  `Position.open(…, stopLoss, takeProfit)` → 리스크 루프의 −1.5%(net) 손절 대상.
- `RiskManagementService.closePosition:198-282` 는 `markRebalanceCooldown()`·`lastTradeTime` 을 건드리지 않는다(갱신은 `TradingBotService.java:610-611, 1003-1004, 330` 뿐).
  → 손절 후 첫 리밸런스 기회(직전 리밸런스 +480분)에 다시 30~70% 매수. §2-3 의 293회/105일 = 8.6시간마다 1회.
- 매도 다리: `sellByClosingProfitablePositions:71-100` 은 net ≥ 0 인 포지션만 **전량** 청산(`sold += p.getEntryVolume()`) → 0.7→0.3 이 아니라 0.7→0 으로 과청산 뒤 재매수(회전 2배).
  하락 국면에선 수익 포지션이 없어 매도 자체가 못 나가고(105일간 리밸런스 매도 0회) 손절이 대신 판다.
- 가드 우회: `buyAndOpenPosition` 에는 서킷브레이커·물타기 차단·노출 상한·maxPositions·미결주문 체크가 하나도 없다(`TradingBotService.executeBuy:445-498` 에만 존재).
  반면 리밸런스 손절은 `circuitBreaker.recordOutcome`(`RiskManagementService.java:251`)로 카운트돼 **신호 매수만** 막는다.
- 영향: §2-3 표 1행. 리밸런스 포지션을 손절에서 면제하면(P1-3 이전) −11.8%, 리밸런싱을 끄면 −2.1%.
- 선행: 05-30 P1-3(리밸런스 Position 생성)·P2-11(핑퐁 쿨다운)로 **회계는 맞췄지만 기대값은 검토되지 않았고, P1-3 이 이 루프를 만들었다.**
  ADR risk/0002 는 maxPositions 우회만 의도로 기록.

### F8 [medium] ATR 동적 비중은 항상 35% [V]

## 4. 반박·유보·한계

- 표본 창 105일은 하락·저변동 구간(ADA 265~319원)이다. 변동성이 커지면 F3 의 신호 빈도와 F5 의 선도달 비율은 달라진다. **그러나 F1(루프 구조)·F2(동결)·F4(틱)·F6(증거 부재)은 국면과 무관하다.**
- 리플레이의 mid 는 최근 체결가다. 실제 호가 mid 는 체결 없이도 움직이므로 손절이 임계에 더 가깝게 잡힌다 — 그래서 "임계가 체결" 낙관 상한(−57%)을 같이 실었다. 두 값 사이 어디든 결론은 같다.
- 리플레이 시작 상태는 전액 현금이다. 코인을 들고 시작해도 첫 손절 뒤엔 같은 루프에 들어간다.
- 완성봉 기준 재현이 기본이다. 동결 모델(40% 스텁)은 가정이며, 표에서 보듯 결과를 바꾸지 않는다 — 동결은 지표 품질 문제이지 손실의 주범이 아니다.
- 서버 실계좌의 체결 이력은 보지 못했다(로컬 DB·로그는 테스트 산출물). 리플레이 수치는 예측이지 실적이 아니다 — §7 로 대조한다.
- "1분봉 RSI 가 몇 배 노이지" 류의 정성 주장은 쓰지 않았다. 수치는 전부 실데이터 또는 코드 산술이다.

## 5. 수익이 나려면 참이어야 하는 것

1. 리밸런싱이 꺼지거나, 손절 루프가 끊기고 회전이 자본의 월 1배 이하로 줄어야 한다.
2. 진입 신호가 ≤6h 안에 **≥ 0.85%(비용) + 손절 확률 가중분** 의 전방수익을 가져야 한다 — 현 시장 360분 p75(1.42%)에 가까운 예측력.
3. 그 신호가 통계적으로 검증될 만큼 자주 나와야 한다 — 현재 월 한 자릿수.
4. 지표 입력이 완성봉이어야 한다.

어느 것도 현재 충족되지 않는다.

## 7. 사용자 확인 사항 — 서버 실적과 대조

`/trading/analytics?days=90` 에서 다음을 읽으면 §2-3 예측을 실적으로 검증할 수 있다.

1. **커버리지 패널**: 신호 행 수, BUY/SELL 수, 청산 포지션 수. 예측: BUY 월 한 자릿수, 청산 대부분이 리밸런스 기원.
2. **청산사유별 표**: STOP_LOSS 비중·평균 pnl. 예측: 건수 최다, 평균 −1.7~−2.3%.
3. **비용 현실**: fees/gross. 예측: 100% 초과(총이익보다 수수료가 큼).
4. 가능하면 `trading_trades` 에서 `signal_reason='Rebalancing buy'` 건수 vs `'Auto buy signal'` 건수.

이 예측이 틀리면(예: STOP_LOSS 가 소수, fees/gross < 50%) §1 판정을 재검토해야 한다.
