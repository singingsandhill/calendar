# ADR-0012: 인기 순위 정렬 — 표수 우선, 동점은 최근 등록 우선

| 항목 | 값 |
|---|---|
| 상태 | Accepted |
| 날짜 | 2026-10-13 |
| 도메인 | datedate |
| 관심사 | 도메인 모델 |
| 관련 커밋 | `docs/guides/git-commit.md` Commit 198 (use-case 본문 렌더 복구와 합본 — 메시지 파일 공유) |
| 관련 이슈 | — |

## Context — 무엇이 문제였나

- AdSense "가치가 별로 없는 콘텐츠" 4번째 통지(2026-10-12) 진단 중, 홈 첫 화면의 "지금 인기있는 선택" 이
  마라탕 4표 → 양식 2표 → 곱창 7표 순으로 나오는 것을 라이브에서 확인했다. `/insights/trends` 도 같은 목록을 쓴다.
- 원인은 표시와 정렬의 기준이 달라서다. 화면에는 집계 표수(`totalVotes`)만 보여주는데, 정렬은
  `표수 + 최근 보너스(등록 후 30일 동안 0~5)` 점수로 했다. 최근 등록된 4표 항목(4+5=9)이 40일 된 7표 항목(7)을 앞질렀다.
- 리뷰어와 사용자에게는 정렬이 깨진 목록으로 보인다 — 통지문의 "구조적 유지관리" 기준에서 품질 결함 신호다.
- 노출 기준(최소 2표 + 비속어 블록리스트)은 [ADR 0006](0006-popularity-exposure-criteria.md) 의 결정이고, 점수식은 그 Context 에
  적힌 기존 동작이었다. 정렬 기준을 바꾸는 것은 0006 의 범위("블록리스트 토큰 추가") 밖이라 새 ADR 로 남긴다.

## Decision — 무엇을 골랐나

집계 표수 내림차순, 표수가 같으면 최근 등록(`latestCreatedAt`) 내림차순으로 정렬한다. 최근 보너스는 없앤다.

- `PopularityService` 의 장소·메뉴 두 파이프라인이 같은 비교자 `BY_VOTES_THEN_RECENCY` 를 쓴다.
  홈·`/insights/trends`·`InsightsService` top 세 소비처가 함께 바뀐다.
- 노출 기준(ADR 0006)은 그대로 — 필터 후 정렬, limit 도 그대로.
- `/insights/trends` 의 "순위 계산 방식" 설명·SEO 설명에서 시간 가중치 문구를 걷어낸다(ko·en).

## Rationale — 왜 이 선택인가

| 대안 | 장단점 | 기각 이유 |
|---|---|---|
| 표시만 바꾸기 (홈에서 표수 숨김, 정렬 유지) | 템플릿만 수정 | 인사이트 페이지는 표수 표를 그대로 보여주고, "왜 이 순서인가" 를 설명할 수 없는 목록이 남는다 |
| 점수를 함께 표시 | 순서와 숫자가 일치 | "9.0점" 같은 내부 점수는 사용자에게 의미가 없다 |
| 최근 N일 창의 표수로 정렬 | "트렌드" 의미 유지 | 일정 2,171건 규모에서 창을 자르면 2표 기준을 넘는 항목이 거의 남지 않는다 |
| **표수 우선 + 최근 동점 처리 (선택)** | 보이는 숫자 = 순서. 동점에서만 최근성 반영 | 오래된 다득표 항목이 오래 남는다 — 아래 Consequences 에서 수용 |

## Consequences — 영향

- **긍정:** 화면의 숫자와 순서가 항상 일치한다. 회귀 가드 `PopularityServiceTest.ordersByVotesBeforeRecency`
  (최근 4표 vs 40일 전 7표 — 라이브 사례 재현, 변경 전 RED 확인) 와 `breaksVoteTiesByRecency`(입력 순서 두 가지로 동점 처리 확인).
- **부정:** "트렌드" 성격이 약해진다 — 오래전에 표를 많이 받은 항목이 상위에 계속 남을 수 있다.
  페이지 제목 "인기 트렌드 & 이용 현황" 은 SEO 영향 때문에 바꾸지 않았다.
- **후속:** 오래된 항목이 상위를 독점하는 것이 관측되면 기간 창 집계를 다시 검토한다(새 ADR).
